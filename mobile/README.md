# My Mate Geny Android

Capacitor shell around the live console of **your own** My Mate Geny server,
with its mobile layout. Native: notifications (LocalNotifications), hardware
back button (closes the top overlay, then backgrounds the app), status
bar/safe areas, file chooser + camera for uploads, downloads (DownloadManager
with the login cookie → Downloads folder), microphone for talking to the Mate
(RECORD_AUDIO, asked when the page requests it; media plays without a tap so
replies can be read aloud), offline page.

## Connecting to a server

No server is built in (`capacitor.config.json` has no `server.url`). The app
starts on the local connect page `www/index.html` (served at
`https://localhost/`): **Server address**, **Username**, **Password** (Show),
*Remember the server and username* — the password is never stored.

- `www/connect-core.js` (identical to `desktop/src/connect-core.js`; both
  test suites check) normalizes the address and probes `/health`: explicit
  scheme only that one; no scheme → https first, http first for localhost,
  private/link-local/CGNAT IPs, LAN names and explicit non-443 ports;
  sub-paths kept; redirects followed. Same messages as the desktop (*Can't
  reach the server*, *Not a My Mate Geny server*, *Wrong username or
  password*, *Too many attempts — try later*, certificate errors). See
  `desktop/README.md` for the full rules.
- HTTP goes through Capacitor's native **CapacitorHttp** plugin, called
  directly (`Capacitor.nativePromise`) from `www/connect.js` — no CORS and no
  mixed-content block for `http://` LAN servers. `plugins.CapacitorHttp.enabled`
  stays off on purpose: it would also reroute the console's own fetch/XHR.
- After `POST /api/auth/login {…, exchange: true}` the page hands the server
  and `{server}/auth/exchange?code=…&next=/` to the **GenyServer** plugin
  (`android/app/src/main/java/me/hrletsgo/harnessor/GenyServerPlugin.java`).
  It saves the server and recreates the activity with Capacitor's
  `server.url` = the server's origin, `server.appStartPath` = the exchange URL
  (then its sub-path on later starts) and `server.allowNavigation` = its host
  — the same setup the app had when the server was hard-coded, so the
  console gets the native bridge on its own origin. The exchange response
  sets the session cookie first-party; the console loads as before.
- Later starts open the saved server directly; an expired session shows the
  server's own `/login` page.
- Back to the connect page: the launcher shortcut **Switch server**
  (long-press the icon), the offline page's *Switch server* button, or from
  any server page `Capacitor.nativePromise("GenyServer", "switchServer")` /
  `…("GenyServer", "signOut")` (sign out also clears the cookies). Local
  pages can navigate to `https://localhost/__geny/{retry,switch-server,sign-out}`.
- Not remembered: the server and its cookies are dropped at the next cold
  start.
- Upgrading from 0.3 (the original author's server was built in): an install
  still signed in there keeps using it; otherwise it is prefilled
  (`LEGACY_SERVER` in GenyServerPlugin.java, used for nothing else).
- **Cleartext**: `android:usesCleartextTraffic="true"` (and
  `server.cleartext`) so `http://192.168.x.x:port` servers on the home
  network work in the WebView and native HTTP; Android 9+ blocks them
  otherwise. https servers are unaffected.

## Build and test

- `npm ci && npx cap sync android && (cd android && ./gradlew assembleRelease)`
  (`android/app/src/main/assets/` is generated by `cap sync`, not committed).
- Unit tests: `npm test` (the page scripts in a sandbox with a fake native
  CapacitorHttp, against `desktop/test/mock-server.js`).
- End-to-end on an emulator/device with a debug build:
  `node test/e2e/android-e2e.js android/app/build/outputs/apk/debug/app-debug.apk`
  (connect over http to the host's mock server as `10.0.2.2`, native bridge on
  the server origin, relaunch, expired session, switch server, sign out,
  offline page Retry/Switch, launcher shortcut, remember off, 0.3 migration).
- Release signing via env: `HRH_KEYSTORE_FILE`, `HRH_KEYSTORE_PASSWORD`,
  `HRH_KEY_ALIAS`, `HRH_KEY_PASSWORD` (GitHub secrets in CI). Keep the
  keystore: every update must be signed with the same key (the maintainer's
  backup lives on their runtime server in `~/.hr-harnessor/android-signing/`;
  forks sign with their own key and a different `appId`).
- Icons/splash: `npm run icons` regenerates `android/app/src/main/res` from
  `assets/` (made by `scripts/make-icons.py` from `assets/geny-logo.png`).

Naming: shown as **My Mate Geny** (`appName`, `app_name`); the package id
`me.hrletsgo.harnessor` and the signing key are unchanged, so existing installs
update in place. Version: `versionName`/`versionCode` come from CI
(`0.4.<run>` / run number); local builds default to 0.4.0-dev / 4.
