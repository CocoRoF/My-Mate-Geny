# 메이트 출처 기반 기억 구현

기준 검토: [2026-11-05 심층 검토](mate-memory-review-20261105.md), 기준 코드 7726ee9.
최초 구현은 임시 DB와 합성 자료로 검증했다. 후속 수정에서는 사용자가 제시한 직장 동료 사례의 원문·처리 상태·첨부 출처를 제한적으로 확인했다.

## 구현 계약

기존 Claude/Codex 실행 경로, 메이트 격리, 대화 방식 prefs의 우선순위, 음성 조각 합치기와 화면 공유 허용 범위를 유지한다. 새 벡터/그래프 서비스나 모델 패키지를 설치하지 않는다. 음성 공급자의 OpenAI 키를 기억 처리에 재사용하지 않는다.

- SQLite에 원문 ID·revision·해시, 인용 범위, 기억 revision과 수정자, 사건·관계, 재처리 대기열, 작업 요청·결과를 추가했다. 기존 메모 ID와 CRUD는 유지한다. 과거 메모에 가짜 원문을 채우지 않는다.
- 메시지 저장과 처리 대기열을 동일 트랜잭션에 넣는다. 중첩 트랜잭션은 savepoint를 쓰며 DB와 메모 저장소는 동일한 재진입 락으로 순서를 통일한다. 인덱스 장애 때 채팅은 남고 dirty outbox에서 복구한다. 수정 대기 중인 낡은 근거는 반환하지 않는다.
- 정확히 동일한 주장만 중복 처리한다. 유사한 문장은 검토 후보이며 날짜·부정·조건이 다른 문장을 길이로 덮어쓰지 않는다. 수정은 새 revision을 만들고 `expected_revision` 불일치는 409로 거절한다.
- 인용은 전체 저장 문장을 지지하는 정확한 원문 인용이어야 한다. 기억 revision별로 연결하므로 수정 전 근거가 새 주장에 그대로 붙지 않는다. 원문 정정은 현재 revision의 자동 추출 기억을 이력과 함께 보관 처리하고, 캐시된 핵심 프롬프트·전달 상태·다른 창의 기억 화면도 갱신한다. 시간 조회 `recall(as_of)`는 **그때 기록되어 있던 내용**이며 실제 사건 발생 시점과 구분한다. 사건 날짜가 원문에 명시되지 않았으면 unknown이다.
- 기한이 지난 계획을 자동 완료하지 않는다. 계획을 기억하는 것과 실제 알림·실행 예약을 구분한다. 활성 기억 500개에서 낮은 우선순위를 보관하며, 보관 기록을 2,000개 제한으로 삭제하지 않는다.
- 메이트 자신의 원문과 작업 세션 원문을 FTS로 검색한다. 기본 범위는 해당 메이트이고 다른 메이트의 대화는 반환하지 않는다. 일반 작업 세션은 기존 메이트의 세션 열람 권한과 같은 범위다. 공급자 계정을 사용자 정체성으로 사용하지 않는다.
- 질문의 표현·별칭을 `aliases`로 함께 찾고, 원문에서 확인된 사건 ID·이름을 통해 최대 2단계 연결한다. 의미 표현 확장은 현재 대화 모델의 질의 계획을 사용한다. 별도 임베딩 API 호출은 없다. 후보 상한에 도달하면 이를 응답에 표시해 검색어/시각 범위를 좁힐 수 있다.
- 원문은 검색 결과 위치 또는 cursor에서 열 수 있다. 한 원문 최대 6,000자, 전후 최대 3개씩 합계 12,000자 이내로 읽고 긴 원문은 `next_offset`으로 계속 읽는다. 원문은 명령이 아닌 비신뢰 자료로 표시한다.
- 사용자 발언, 메이트 보고, 실제 도구 실행 영수증을 구분한다. 자신의 응답을 사용자 확인으로 승격하지 않는다.
- 삭제는 기억·버전·인용·연결된 사건을 제거하고 원문 ID와 내용 해시를 재추출 제외표에 남긴다. 원래 채팅은 화면에 남지만 해당 메이트의 기억 검색에서는 제외한다. 원문 채팅 자체를 삭제하면 연결된 파생 기억과 FTS도 지운다.
- 잊기 이후 이전 CLI 대화는 재개하지 않고, 압축/초기화 이후에는 전달 상태를 다시 계산한다. 전달 실패한 턴은 기억 변경 알림을 소비하지 않는다. 진행 중이던 옛 턴이 늦게 CLI ID를 써도 privacy generation으로 새 턴을 강제한다.

## 자동 정리

`self_save`가 켜진 메이트의 **새로 확정된 사용자 발언**을 처리한다. 미완성/취소 음성 입력, 자동 화면 관찰, 인사·내부 트리거, 인증 정보가 있는 원문은 제외한다. 과거 원문은 모델 호출 없이 검색 가능하게 backfill하며, 특정 과거 원문의 정리는 사용자가 버튼으로 요청할 수 있다.

해당 메이트가 응답 중이지 않을 때 새 발언을 최대 8개씩 묶어 처리한다. 일반 작업 채팅의 실행 여부는 추출을 막지 않는다. 최근 18개 발언의 대화 순서와 기존 관련 기억을 함께 제공해 앞뒤 발언의 이름·대명사·관계를 연결한다. 문맥은 기본 16,000자, 발언별 모델 입력은 3,000자 이내이며 처리 중인 발언의 발췌를 우선 보존한다. 한 번에 사실 8개·사건 4개 이내다. 근거는 현재 원문 revision의 정확한 인용이며 여러 발언의 인용을 합친 기억은 모든 근거를 함께 연결한다. 출처가 없는 선택적 인물 라벨은 버리며 유효한 인용까지 버리지 않는다. 특정 이름·기억 요청 문구를 탐지해 저장하지 않고, 메이트 본 대화의 프롬프트나 도구 호출에 저장을 의존하지 않는다.

추출은 단일 worker에서 최대 분당 2회이며 하루 24회 중단 조건은 제거했다. 실패는 지수 지연으로 최대 3회 재시도하고 하트 패널에서 실패한 정리만 다시 요청할 수 있다. `memory_runs`에 배치별 시작·종료·상태·반영 수를 기록하며 사용량은 배치당 한 번만 기록한다. 재시작은 실행 중이던 작업을 복구한다. 구 단일 발언 추출기가 완료 처리했지만 근거 기억을 남기지 않은 발언은 버전 이관 때 한 번 다시 처리하며, 잊은 원문과 꺼진 self_save를 우회하지 않는다. 과거 원문 인덱싱은 전체 유휴 상태에서 100개 묶음으로 처리하고 메시지마다 DB 잠금을 푼다. `MEMORY_CONSOLIDATION_ENABLED=false`로 자동 worker를 멈출 수 있다. 저장 직전에 self_save와 원문 revision·삭제·망각 상태를 다시 검사한다.

기존 공급자와 계정 풀을 사용하지만 별도의 봉인된 요청을 만든다. 도구·MCP·플러그인·첨부·사용자 설정이 없으며, Claude의 `--no-session-persistence`, Codex의 `--ephemeral`을 적용한다. Codex의 도구 제거용 모델 카탈로그가 없으면 도구가 있는 설정으로 대체하지 않고 실패 처리한다. 원문 인용과 일치하지 않는 후보는 저장하지 않는다. 실패해도 원문 검색은 유지된다. 추출 비용·토큰은 내용 없이 기존 7일 사용량의 내부 호출에 기록한다. 보고된 비용이 없는 엔진의 실제 비용을 무료라고 단정하지 않는다.

## 화면 공유 첨부

첨부에 신뢰된 캡처 경로에서만 기록하는 `origin=screen`을 추가했다. 모델에는 그대로 전달하되 live user.message/user.steer, 전체/페이지형 대화 이력과 첨부 렌더러에서는 숨긴다. `screen-*.png`라는 이름만으로 판단하지 않으므로 직접 첨부한 파일은 계속 보인다. 과거 artifact/화면 관찰 출처는 이관하며, 출처를 남기지 않았던 과거 on-turn 캡처는 이름만으로 일괄 변경하지 않는다. 사용자가 신고한 두 건은 백업 후 해당 메시지·첨부를 정확히 지정해 출처만 복구한다.

## 작업 복구

작업 채팅 하나를 키로 덮어쓰지 않고 위임마다 요청 ID를 부여한다. 요청, 보고, 백그라운드 진행, 중단과 영수증 revision을 SQLite에 남긴다. 수락한 결과 메시지에 영수증 ID도 남겨 재시작 후 중복 전달을 막으며 중간 보고와 최종 보고를 구분한다.

재시작 시 결과가 불확실한 외부 작업은 자동 재실행하지 않는다. 상태는 unknown/미확인으로 복구하고 원본 실행 기록을 열게 한다. `ok` 응답 자체는 글 발행이나 배포 성공 증거가 아니다. 같은 worker 턴에 여러 요청이 들어간 경우 영수증의 시간 범위를 공유한다고 표시하며 배타적인 작업별 실행 증거라고 주장하지 않는다.

## UI와 API

메이트 헤더의 하트 패널이 기억과 관계 관리의 진입점이다. 일반 메이트 설정에서는 두 탭을 제거했다. 웹과 데스크톱 채팅 창 모두 같은 패널에서 관리한다. 기억은 사람·취향·약속·함께한 일 분류, 검색, 카드별 편집·보관·잊기·근거/이력, 사건별 원문/망각을 제공한다. 자동 정리의 대기·실패·최근 반영 수를 표시하고 기억 사용 설정과 원문/작업 검색은 접어서 제공한다. 기존 settings-memory/settings-relation 링크도 하트 패널로 연결한다. 모바일 터치와 키보드로 사용할 수 있다. 관리자 → 시스템은 원문 수, 사건 수, 대기·실패·인덱스 대기, 평균 처리 시간과 기록된 비용만 표시한다.

기존 CRUD 외에 추가한 인증 API:

```
GET    /api/mates/{id}/knowledge/search?q=&scope=mate|sessions|all&since=&until=&offset=&limit=
GET    /api/mates/{id}/knowledge/evidence/{source}?revision=&before=&after=&offset=
DELETE /api/mates/{id}/knowledge/evidence/{source}
GET    /api/mates/{id}/memories/{memory}/history
POST   /api/mates/{id}/memories/{memory}/restore-version {revision, expected_revision}
GET    /api/mates/{id}/knowledge/status
GET    /api/mates/{id}/knowledge/tasks
GET    /api/mates/{id}/knowledge/tasks/{request}/receipts/{event}
POST   /api/mates/{id}/knowledge/process-source {source_id}
GET    /api/mates/{id}/knowledge/episodes?before=&limit=
POST   /api/mates/{id}/knowledge/retry
```

메이트의 좁은 도구도 같은 저장·권한 경로를 사용한다: `search_history`, `read_evidence`, `record_episode`, `get_episode`, `list_task_records`, `get_task_record`, `read_task_receipt`.

## 확인 기록

- 최초 핵심 회귀 44개 통과. 이후 인용 revision, dirty outbox, 삭제 중 진행 요청, 긴 원문 paging, 영수증 복구, API 충돌 검증을 추가했다.
- 격리된 실제 FastAPI + 빌드된 웹 UI + Chromium에서 데스크톱/모바일 9개 조작 확인. 검색·원문·버전 복원·409 충돌·작업 기록·터치·가로 넘침 없음·망각을 확인했다.
- 합성 메시지 10,000개, 사건 1,000개, 검색 40회: p50 44.90ms, p95 45.36ms, 초기 인덱싱 46.08초. 이 서버의 단일 프로세스·합성 자료 측정이며 운영 규모 전체의 지연을 보장하는 수치는 아니다. 외부 호출 0회.
- 최종 전체 백엔드 **866개 통과, 3개 기존 skip**. 프런트엔드 단위 **154개**, 데스크톱 단위 **154개**, 언어 키/문구 검사 및 프런트 빌드 통과. 후속 엔진 캐시·근거 변경에 대해서는 메이트 범위 회귀도 별도로 실행했다.
- 후속 문맥 자동 기억 수정: 백엔드 전체 **877개 통과, 3개 기존 skip**, 프런트·데스크톱 각 **154개 통과**, 타입·언어 키 검사 통과. 실제 Claude Sonnet 5.5와 Codex GPT-6.1-Sol에 합성 대화를 제공해 명시적인 저장 요청 없이 인물 관계와 취향이 저장되고 두 사용자 발언의 근거가 연결되는 것을 확인했다. 이 작은 사례 검증을 전체 기억 정확도 평가로 간주하지 않는다.
- 하트 패널의 웹·모바일·데스크톱 채팅 UI 15개 동작을 확인했다. 캡처 숨김과 일반 이미지 유지, 새로고침, 분류·검색, 두 근거 열기, 고정·날짜 약속 추가·버전 복원, 관계 설정 이동, 창 사이 자동 기억 설정 동기화, 사건 망각과 과거 링크를 검증했다. 후속 증거는 `.claude/verification/mate-memory-fixes-20261105/`에 저장했다.
- 배포는 다른 대화가 3분간 쉬는 것을 확인한 뒤 운영 DB 백업 → 백엔드 재시작 → 웹 원자 교체 → 새 API/빌드 식별자 확인 순서로 적용한다. 최초 적용 상태는 `/home/hrjang/.cache/hrh-memory-verify/deployment-status.json`, 후속 문맥 기억·하트 패널 수정 적용은 `/home/hrjang/.cache/hrh-memory-fixes/deployment-status.json`에 기록한다. 신고된 캡처 출처 복구와 정상 worker의 두 원문 근거 복구 여부도 별도 진단 파일에 남긴다. 서버 접속 앱은 새로고침으로 적용되고 로컬 실행 앱은 새 번들 빌드가 필요하다. 네이티브 릴리스 결과는 사용자가 확인한다.

미확인 범위: 운영 개인 기록의 정답률, 실제 음성·이미지에서 장기 사건을 추출하는 성공률, 공개 LongMemEval/LoCoMo 전체 점수, Windows/macOS 실제 설치 실행. 원문에 전혀 없는 정보를 복구했다고 주장하지 않는다. 외부 사진 보관함·메일·캘린더를 새로 수집하거나 실행 예약 시스템을 추가하지 않았다.
